# Навык: n8n Idempotent CRM Pipelines

Этот навык определяет правила построения непадающих сценариев в n8n с гарантией идемпотентности при интеграции с CRM (Битрикс24).

## 1. Отказоустойчивость и Auto-Retry
* Все критические HTTP-ноды (обращения к внешним LLM, локальным RAG-парсерам, REST API Битрикс24) обязаны содержать:
  * `retryOnFail: true`
  * `maxTries: 3..5`
  * `waitBetweenTries: 15000..30000` (15–30 секунд)
* Это позволяет процессам выдерживать кратковременные перезапуски контейнеров и минутные сетевые кулдауны без аварийного завершения.

## 2. Защита от дублей сделок (Идемпотентность)
* **Запрет на слепой `crm.deal.add`:** При ручном перезапуске упавшего воркфлоу (Retry execution) или автоматических ретраях повторное создание сделки строго запрещено.
* **Схема проверки:**
  1. Перед созданием сделки выполнить поиск `crm.deal.list` по `CATEGORY_ID=4` с фильтром по уникальному `folderId` (в `COMMENTS`) или номеру процедуры `UF_CRM_TP_11`.
  2. Если сделка уже существует — извлечь ее существующий `ID` и направить поток данных сразу к созданию задач/чатов, минуя ноду добавления сделки.

## 3. Диагностика логов в SQLite n8n
* В базе `/Storage/docker/n8n-eng/n8n_data/database.sqlite`:
  * Таблица `execution_entity` содержит статусы и время запусков.
  * Таблица `execution_data` содержит сериализованный flatted-граф ошибки.
  * **Отличие Error Trigger от реального выполнения:** Успешный запуск ноды `Error Trigger` (`Succeeded in <1s`) означает лишь отправку системного алерта об ошибке в чат. Реальная ошибка содержится в предшествующем execution.
