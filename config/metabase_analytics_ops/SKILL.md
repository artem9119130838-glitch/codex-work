# Навык: Metabase Analytics and Security Operations

Этот навык содержит готовые регламенты, SQL-шаблоны и API-сценарии для администрирования Metabase, построения аналитических воронок и настройки прав доступа.

## 1. Построение SQL-воронок и агрегаций
При построении отчетов в Metabase (PostgreSQL / SQLite):
* **Защита от сбоев кодировок Windows/SSH:** При фильтрации стадий в SQL-запросах всегда использовать латинские ID стадий (из `raw_data->>'STAGE_ID'` или системных констант `WON`, `C4:EXECUTING`), а не кириллические названия.
* **Итоговые строки и расчет дельт:** Для таблиц выигранных сделок выводить 4 обязательных финансовых столбца:
  1. `НМЦК (руб)` — `initial_sum`
  2. `Сумма контракта (руб)` — `final_deal_sum`
  3. `Разница (руб)` — `initial_sum - final_deal_sum`
  4. `Снижение (%)` — `ROUND((initial_sum - final_deal_sum) / NULLIF(initial_sum, 0) * 100, 2)`
  В визуализации Metabase настраивать закрепленную строку `ИТОГО` с суммой по деньгам и средним значением по проценту снижения.

## 2. Разграничение прав доступа (Community Free Edition)
В бесплатной версии Metabase опция прямого запрета баз данных `"blocked"` недоступна (вызывает ошибку 500 и требует Enterprise-лицензию).
* **Скрытие баз данных и раздела «Данные» от менеджеров:**
  1. Перевести группу «All Users» (ID 1) в режим `"view-data": "legacy-no-self-service"`.
  2. Установить `"create-queries": "no"`.
  3. Это скрывает вкладку сырых данных и конструктор запросов у обычных пользователей, оставляя администраторам полный неограниченный доступ (`"view-data": "unrestricted"`, `"create-queries": "query-builder-and-native"`).
* **Изоляция коллекций менеджеров:**
  1. Создать отдельную коллекцию (например, «Аналитика для менеджеров»).
  2. Для группы «All Users» установить права `read` только на эту коллекцию, а на корневую коллекцию и служебные разделы установить `none`.

## 3. Резервное копирование базы данных Metabase (H2)
* Файл базы данных Metabase во встроенном режиме хранится по пути `/Storage/docker/metabase_data/metabase.db/metabase.db.mv.db`.
* **Регламент бэкапа:**
  1. Временно остановить контейнер: `docker stop metabase`.
  2. Скопировать `metabase.db.mv.db` в каталог бэкапа.
  3. Запустить контейнер: `docker start metabase`.
  4. Процедура включена в еженедельный скрипт сервера `/Storage/run_server_backup.sh`.

## 4. Сброс паролей пользователей в базе данных Metabase (H2)

При необходимости сбросить пароль пользователя (например, администратора) напрямую через базу данных H2 (когда доступ к UI утерян):
* **Критическая особенность безопасности:** Metabase не хэширует чистый пароль напрямую. Он конкатенирует его с солью пользователя из колонки `PASSWORD_SALT` (формат UUID).
* **Формула строки для хэширования:** `PASSWORD_SALT + ЧИСТЫЙ_ПАРОЛЬ` (например: `31d14741-1925-47cd-a9a0-424240bc5501Artem12345`).
* **Алгоритм хэширования:** bcrypt версии `$2a$` с 10 раундами сложности.

### Пошаговый алгоритм сброса:
1. Остановить контейнер Metabase на сервере:
   ```bash
   docker stop metabase
   ```
2. Подключиться к H2 базе данных и получить соль (`PASSWORD_SALT`) нужного пользователя:
   ```sql
   SELECT PASSWORD_SALT FROM CORE_USER WHERE EMAIL = 'user@example.com';
   ```
3. Сгенерировать новый хэш в Python на сервере, используя полученную соль:
   ```python
   python3 -c "import bcrypt; print(bcrypt.hashpw(b'UUID_СОЛИ' + b'НОВЫЙ_ПАРОЛЬ', bcrypt.gensalt(prefix=b'2a', rounds=10)).decode('utf-8'))"
   ```
4. Обновить хэш пароля в базе данных:
   ```sql
   UPDATE CORE_USER SET PASSWORD = 'НОВЫЙ_ХЭШ' WHERE EMAIL = 'user@example.com';
   ```
5. Запустить контейнер Metabase:
   ```bash
   docker start metabase
   ```
