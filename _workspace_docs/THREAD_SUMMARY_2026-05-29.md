## Почему GitHub «не заменяет ПК», хотя всё через GitHub

- GitHub хранит только **каноническую часть** (доки/KB/скрипты/золотые данные). Это сознательно.
- Локально остаются:
  - сырые входные файлы (например тендеры),
  - большие legacy,
  - кэши/временные результаты,
  - любые секреты/.env (их нельзя коммитить),
  - всё, что нужно для работы офлайн.

## Как работать 2–3 месяца только с ноутбука (рекомендуемый сценарий)

### Правило №1
Пока ты на даче: **работа только с ноутбука**. Домашний ПК не меняет E:\Codex_Work.

### Шаги на ноутбуке (один раз)
1) Установить Git for Windows.
2) Сгенерировать SSH-ключ **на ноутбуке** (у каждого устройства свой ключ).
3) Добавить публичный ключ ноутбука в GitHub: Settings -> SSH and GPG keys.
4) Клонировать репозиторий на локальный диск ноутбука (рекомендуется):
   - git clone git@github.com:artem9119130838-glitch/codex-work.git D:\Codex_Work
   - (или C:\Codex_Work, если на C достаточно места)

### Ежедневный цикл на ноутбуке
- Работаешь в D:\Codex_Work.
- Регулярно делаешь git status → git add → git commit → git push.
- FreeFileSync использовать только как **backup в одну сторону** (mirror):
  - Source: D:\Codex_Work
  - Target: внешний диск (backup папка)
  - НЕ делать двустороннюю синхронизацию между ПК и ноутом.

## Когда вернёшься домой

- На домашнем ПК в E:\Codex_Work просто сделать:
  - git pull

Не нужно вручную «выбирать папку» и копировать туда-сюда.

## Если что-то пойдёт не так

- Ошибка Permission denied (publickey) на ноутбуке → значит SSH-ключ ноутбука не добавлен в GitHub.
- Ошибка Host key verification failed → один раз принять host key (мы уже делали это на ПК).

## Пояснение (дословно из чата): почему «чистый ноутбук» может продолжать

> "GitHub не заменяет локальные ПК, потому что мы специально не коммитим всё подряд: сырые входняки, ARCHIVE/, большие legacy, кэши, временные результаты, .env/секреты — это остаётся локально/в бэкапах. GitHub держит канон: KB/доки/шаблоны/скрипты/data/gold/.codex без stages."

Ты сможешь продолжать “как будто с этого ПК” **только в той части, которая лежит в GitHub** (канон). А “не всё подряд” — это про тяжёлые/сырые данные, которые для продолжения *обычно не нужны каждый день*.

Разложу по‑простому:

### Что будет на ноутбуке после git clone
Будет ВСЁ, что нужно, чтобы продолжать управление системой:
- codex_kb (правила, runbooks, прогресс)
- мастер‑файлы корня (AGENTS.md, PROGRESS.md, etc.)
- _templates, _workspace_docs
- пилотный проект (в разрешённой части)
- история изменений (git)

То есть “мозг и память” системы — на месте.

### Чего на ноутбуке НЕ будет (и это нормально)
Не будет того, что мы сознательно не коммитим:
- ARCHIVE/ (старые черновики/файлы)
- incoming/ сырые тендеры / большие входные файлы
- processed/outputs/reports если они большие/временные
- кэши, model outputs, batches, candidates
- .env и любые секреты

Это не “сломает продолжение”, потому что:
- 80–90% задач по управлению KB/планам/оркестрации/скриптам можно делать без raw данных
- raw данные подтягиваются **когда реально нужны**, отдельным способом

### Когда станет проблемой, что raw нет на ноутбуке?
Только когда тебе нужно:
- реально разбирать конкретные PDF/ZIP/Excel тендеры
- гонять пайплайн на “сырых” файлах
- проверять большие артефакты, которые не в git

Тогда варианты:
1) Скопировать конкретную партию raw на ноутбук (или на внешний диск) вручную.
2) Держать raw на внешнем диске и подключать к ноутбуку.
3) Позже, если надо, сделать отдельный “raw-storage” (не в git) по правилам.

### Ключевая мысль
“Продолжать работу” = продолжать **каноническую систему** (доки, правила, прогресс, шаблоны, оркестрация).
Это мы уже положили в GitHub.

“Продолжать обработку больших сырых файлов” = отдельная история, это не должно жить в GitHub.
