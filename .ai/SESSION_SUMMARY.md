## 3. Критические ошибки и извлеченные уроки (Lessons Learned)

1. **Multi-Item RFQ Excel Specification Invariant:**
   - Нельзя сжимать сложные многопозиционные заявки в одну строчку заголовка задачи.
   - Любая заявка с $>1–2$ позициями обязана сопровождаться двуязычным чистовым Excel-файлом по мастер-шаблону `D:\Документы Victus\Рабочее\Шаблоны\Заявки\Запрос КП пример заполнения.xlsx`, прикрепленным к задаче на Диске группы 14.
2. **Zero Mention When Empty Invariant:**
   - Если в заявке нет чертежей/файлов, **категорически запрещено упоминать их в теле задачи или чате**. Любые фразы («Вложения в карточке», «Без чертежей») воспринимаются китайскими коллегами как сигнал к поиску и вызывают блокирующие вопросы.
3. **Bitrix24 Tasks API BBCode Hygiene:**
   - Парсер описания задач Битрикс24 падает с `500 INTERNAL_SERVER_ERROR` при наличии тегов `[TABLE]`, `[TR]`, `[TH]`, `[TD]`. Описание задач должно оформляться структурированными списками и жирным шрифтом без табличного BBCode.
4. **1C:УНФ OData Tabular Section Protocol:**
   - Попытка прямого POST в URL подчиненной таблицы (`Catalog_Лиды(guid)/КонтактнаяИнформация`) возвращает `405 Method Not Allowed`. В 1С:УНФ табличные части обновляются строго через HTTP PATCH на родительский каталог `Catalog_Лиды(guid'...')?$format=json` с передачей массива строк.
5. **Task Deal-Only Binding Invariant:**
   - Поле `UF_CRM_TASK` задачи снабжения должно содержать строго массив `['D_{deal_id}']`. Вызов `crm.activity.binding.add` к контактам и компаниям разрешен только для почтовых активностей (`CRM_EMAIL`).
