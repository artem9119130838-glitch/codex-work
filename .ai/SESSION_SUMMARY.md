## 3. Критические ошибки и извлеченные уроки (Lessons Learned)

1. **Дефект текстовых заглушек при публикации файлов (`Bitrix24 Task & IM Attachment Protocol`):**
   - *Ошибка:* Добавление в комментарий BB-кода `[DISK FILE ID=...]` не прикрепляет файл к задаче в Б24 и выглядит для пользователя пустой заглушкой.
   - *Решение:* Всегда обновлять `UF_TASK_WEBDAV_FILES` в `tasks.task.update` через `['n<id>']`, для чатов использовать `im.disk.file.commit`, а в текст вставлять публичные ссылки `disk.file.getExternalLink`.

2. **Ложноотрицательный подсчет побед (`Cross-Pipeline Won Deals Guard`):**
   - *Ошибка:* Поиск побед строго внутри Категории 4 показал 0, т.к. стадия `C4:WON` переименована в «Не взяли в работу», а реальные победы переводятся в воронку «Заказчики» (Категория 0).
   - *Решение:* Сквозной кросс-воронковый аудит Категории 0 по выигранным стадиям исполнения контракта.

3. **Слепая склейка задач (`No-Blind-Task-Attribution Guard`):**
   - *Ошибка:* Алгоритм взял `tasks[0]` и зацепил техническую задачу анализа Сауле на саму себя (`=Проанализировать...`, Группа 0), приписав ей 74 срыва китайских фабрик.
   - *Решение:* Задачи снабжения фильтруются строго по `GROUP_ID == 14` и привязываются строго к закупщикам (Miss Wang, Азат), а задачи анализа и подготовки КП исключаются из оценки снабжения.
