## 3. Критические ошибки и извлеченные уроки (Lessons Learned)
- **Удаление файлов в Windows root C:\\:** Обычный непривилегированный процесс не имеет прав `Delete` в корне `C:\`. Для удаления/переименования папок в корне `C:\` требуется запуск командлета через `Start-Process powershell -Verb RunAs` или явное администрирование ACL.
- **Git Read-Only блокировка на Windows:** Файлы объектов и паков Git создаются со снятым флагом записи (`stat.S_IWRITE == False`). При удалении дерева репозитория средствами Python стандартный `shutil.rmtree` падает с `[Errno 13] Access Denied`. Необходимо перехватывать `onerror` и вызывать `os.chmod(path, stat.S_IWRITE)`.
- **Подмена USERPROFILE в реестре:** Нельзя устанавливать `USERPROFILE` в реестре `HKCU\Environment` на проектные папки (`C:\codex_home`). Это приводит к тому, что системные процессы Windows (WebView2, Widgets) создают и намертво блокируют `%TEMP%` внутри рабочей директории. `USERPROFILE` и `HOME` должны указывать строго на `C:\Users\Артем`.
- **Особенности WinPE и Macrium:** Среды WinPE (включая JinnLiveUSB) урезаны по библиотекам: вызов `Reflect.exe` требует наличия `oledlg.dll` в каталоге программы. Лоадеры вроде `xReflect.exe` могут блокироваться политиками прав WinPE, поэтому запускать следует оригинальный бинарник `Reflect.exe`.
- **Умное копирование Macrium (Intelligent Sector Copy):** Файлы подкачки и гибернации (`pagefile.sys`, `hiberfil.sys`, `swapfile.sys`) автоматически исключаются Macrium из создаваемого образа системы — удалять их вручную перед бэкапом не требуется и опасно для стабильности ОС.
