## 3. Критические ошибки и извлеченные уроки (Lessons Learned)
- **Инвариант неприкосновенности маршрута 1С на Keenetic:** Попытка исключить `109.248.170.181` из маршрутов роутера недопустима, так как этот туннель критически важен для минимизации сетевых задержек в базах 1С (`unf`, `money`, `buh`). Любые сетевые решения должны учитывать работу поверх существующего туннеля Keenetic.
- **Wintun AllowedIPs Bug на Windows:** Разделение `AllowedIPs = 0.0.0.0/1, 128.0.0.0/1` на Windows лишает драйвер Wintun возможности установить `/32` маршрут к Endpoint через физический шлюз, создавая рекурсивную петлю маршрутизации.
- **MTU Blackhole в многоуровневых туннелях:** Keenetic имеет туннельный лимит `ip mtu 1324`. Стандартный MTU 1420 на клиенте Windows превышает этот лимит и отбрасывается роутером из-за флага Don't Fragment (DF).

## 4. Открытые вопросы и следующие шаги для нового агента
1. **Проверить статус пира Victus на VPS:** Исследовать `/etc/wireguard/wg0.conf` на сервере `109.248.170.181`. Проверить, не завис ли старый handshake и не блокирует ли iptables трафик от IP `10.10.0.5`.
2. **Проверить гипотезу пользователя о пересоздании профиля:** Создать на VPS абсолютно свежий пир (новый приватный/публичный ключ, новый адрес, например `10.10.0.12/32`), сгенерировать чистый `.conf` и протестировать подключение.
3. **Проверить локальные конфликты на ноутбуке Victus:** На ноутбуке запущен `XboxService.exe` с адаптером `vgate0` (также на драйвере Rust Wintun, IP `172.30.205.220`). Исключить конфликт адаптеров Wintun в Windows.
4. **Категорическое требование:** Ни при каких обстоятельствах не менять настройки роутера Keenetic и не удалять маршруты к 1С.
