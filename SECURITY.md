# Decision Policy и Матрица Рисков (Личный контур)

Этот файл регулирует уровень автономии ИИ-ассистента и определяет правила запуска команд и редактирования файлов.

## 1. Матрица уровней риска (L0 - L6)

Каждая задача перед выполнением классифицируется ИИ по уровню риска.

| Уровень Риска | Описание | Что можно делать автономно | Требуется подтверждение |
| :--- | :--- | :--- | :--- |
| **L0: Чтение** | Чтение файлов, поиск текста, индексация. | Полностью автономно (в пределах лимитов по строкам). | Не требуется. |
| **L1: Диагностика** | Запуск безопасных команд опроса (ping, get-process, проверка существования файлов). | Разрешено запускать для исследования проблемы. | Не требуется. |
| **L2: Изменение файлов** | Редактирование локального кода, создание новых скриптов. | Редактирование по согласованному плану или по прямому указанию. | Не требуется в рамках плана. |
| **L3: Изменение инфры** | Изменение системных настроек Windows, реестра, сетевых адаптеров. | Только исследование и планирование. | **Требуется подтверждение** перед применением. |
| **L4: Сеть и Интернет** | Запросы к сторонним API, скачивание пакетов, Curl. | Исследование доступности портов. | **Требуется подтверждение** на внешние запросы. |
| **L5: Git Push** | Отправка изменений в удаленный репозиторий. | Подготовка коммитов локально. | **Требуется подтверждение** (контролируется pre-push хуком). |
| **L6: Production** | Работа с сервером VPS, БД 1С/PostgreSQL, перезапуск служб. | Мониторинг логов и служб (read-only). | **Критический аппрув.** Любое изменение инфры VPS требует явного "Да". |

## 2. Правила минимизации UAC и предотвращения зацикливания

1. **Группировка команд и Script-First**: 
   * Если для решения задачи требуется запустить последовательность из более чем 3-х команд в терминале (локально или по SSH), ИИ обязан объединить их в один исполняемый скрипт (`.sh` или `.ps1`), сохранить его и запросить выполнение **одного скрипта**.
   * Менее 3 команд группировать в одну строку через `&&` или `;` для подтверждения за один клик.
2. **Whitelist для Git**: Пуши разрешены только в репозитории из вайтлиста `C:/codex_home/.git_hooks/allowed_remotes.txt`.
3. **Правило "Stop-on-Fail" для L3-L6**: Если команда с повышенными привилегиями (UAC, sudo, перезапуск служб) или запрос доступа завершились ошибкой, ИИ запрещено повторять аналогичные действия. ИИ обязан остановиться после первой неудачи, доложить об ошибке и передать управление пользователю.
4. **Запрет "слепых" системных действий (1С на VPS)**: Категорически запрещено пытаться настраивать или запускать службы 1С:Предприятия на VPS без проверенного Runbook в `codex_kb/30_runbooks/` или пошаговых инструкций от пользователя.
