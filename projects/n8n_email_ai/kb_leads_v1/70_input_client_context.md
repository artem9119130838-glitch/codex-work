# Input Client Context (входная карточка для генерации письма)

Назначение: стандарт, какие данные нужно собрать перед тем как писать письмо. Если данных нет — письмо должно быть “уточняющим”, а не “расчетным”.

## Минимальный контекст (обязательное)
- Цель письма: `reply` | `follow_up` | `reactivation` | `objection_reply` | `tender_reply` | `after_call_summary`
- Клиент (компания): название (как в переписке)
- Контакт: имя (если известно), роль (если видно), email отправителя
- Тема запроса: товар/направление (1 строка)
- Срочность: есть ли крайний срок (если указан)

## Контекст сделки (желательно)
- Что именно нужно: артикул/модель/количество
- Есть ли поставщик: да/нет; где найден (1688/производитель/другое)
- Есть ли инвойс/КП/ТЗ: да/нет
- Документы: нужны ли НДС, ДТ/ГТД, закрывающие документы
- География: город получения в РФ; (если известно) город отгрузки в КНР
- Ограничения: “только оригинал”, “допускается аналог”, “только официальный импорт”, “можно карго”

## История коммуникации
- Было ли КП/расчет ранее: да/нет
- Последнее касание: дата и канал (email/звонок)
- Что уже отправляли: КП/презентация/документы/ссылки
- Тон клиента: нейтральный | холодный | раздраженный | заинтересован

## Ограничения на упоминания
- Что нельзя упоминать: (например “не обсуждать карго”, “не обещать сроки”)

## Формат для машины (пример)
```json
{
  "goal": "reply",
  "client_company": "...",
  "contact_name": "...",
  "contact_email": "...",
  "topic": "...",
  "items": [
    {"brand": "...", "part_number": "...", "qty": "..."}
  ],
  "has_supplier": null,
  "supplier_source": null,
  "needs_docs": null,
  "deadline": null,
  "city_ru": null,
  "history": {"last_touch": null, "sent_before": []},
  "client_tone": "neutral",
  "notes": null
}
```

Правило: если `needs_docs` неизвестно — прямо спросить, критичны ли документы/НДС/ДТ/ГТД.
