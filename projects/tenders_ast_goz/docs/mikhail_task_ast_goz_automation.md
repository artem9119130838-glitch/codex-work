## 1. Контекст и бизнес-цель

Для работы конвейера анализа тендеров (`tender-rag-api`) требуется регулярная выгрузка 20–30 пакетов тендерной документации с площадки **АСТ ГОЗ (223.astgoz.ru)**.

### Ключевое ограничение контура (Air-Gap / Изоляция):
* Компьютер с АСТ ГОЗ работает через **выделенный криптошлюз (ViPNet Client / Континент АП)** с прямым каналом связи.
* На этой рабочей станции **физически отсутствует публичный интернет** во время сессии ГОЗ (сеть замкнута на шлюз площадки).
* Невозможно отправлять вебхуки наружу, обращаться к облачным LLM или удаленному серверу n8n напрямую из процесса выгрузки.
* Аутентификация и подписание производятся с использованием **локального аппаратного токена ЭЦП (Рутокен/JaCarta) и плагина КриптоПро**.

## 2. Ретроспектива попыток (Архитектурные грабли и почему они провалились)

Ранее было опробовано 4 различных подхода. Михаил, обязательно ознакомьтесь с выводами, чтобы не повторять неэффективные пути:

1. **AutoHotkey (AHK / Координатный кликер и ImageSearch):**
   * *Проблема:* Верстка АСТ ГОЗ динамическая. Высота строк зависит от длины названия лота, шрифты масштабируются Windows DPI, всплывающие окна смещают координаты. Промахи кликов приводили к зависанию. **Подход закрыт как тупиковый.**

2. **Экранный OCR (распознавание текста кнопок через Tesseract/EasyOCR):**
   * *Проблема 1 (Отсутствие контекста строки):* В таблице реестра может быть 20 строк со словом «Запрос документации». OCR видит текст, но не связывает его с конкретным номером процедуры (15-значным ID лота).
   * *Проблема 2:* Огромный оверхед по времени (3–6 секунд на скриншот и инференс) и чувствительность к затемнению фона модальными окнами. **Подход закрыт.**

3. **Консольные Bookmarklets (F12 / Закладки):**
   * *Вывод:* Подтвердил, что прямой DOM-доступ работает, скрытые ссылки строк можно вызывать программно без наведения мыши (`hover`), чекбоксы активируются через `dispatchEvent(new Event('change', { bubbles: true }))`. Но требовал постоянного ручного кликания оператором.

4. **Tampermonkey (State Machine Userscript v1.0 / v2.0):**
   * *Что работало:* Конечный автомат (`IDLE` -> `REQUESTING` -> `UNLOADING` -> `PREPARING`) с хранением состояния в `localStorage`.
   * *Почему сбоил («кривой-косой» вариант):*
     * **Поломка навигации `history.back()`:** После сабмита формы и выгрузки сайт совершает внутренние редиректы, возврат назад по истории выкидывал на пустую страницу или сбрасывал фильтры реестра.
     * **Мутация DOM строки:** После запроса документации строка меняет статус в реестре, скрипт терял привязку к исходному лоту и не мог выставить метку «Подготовить документы».
     * **Гонки таймеров (`setTimeout`):** Нестабильное время отклика защищенного шлюза приводило к тому, что фиксированные таймауты либо не успевали за модалкой, либо вызывали лишние повторные клики.

## 3. Точный DOM-маршрут (10 шагов взаимодействия с площадкой)

Ниже зафиксирована проверенная цепочка селекторов и действий:

1. **Поиск целевого лота в реестре (`/registry/view/pr_lots_all`):**
   * Извлечение 15-значного номера процедуры (`/\d{15}/` или `/\d{8,}/`).
   * Извлечение ссылки запроса документации из строки: `row.querySelector('a[href*="request_documents"]')` или ссылка с текстом `Запрос документации`.
2. **Переход на страницу запроса:** `requestLink.href`.
3. **Установка согласия (чекбокс):**
   * `const cb = document.querySelector('input[type="checkbox"]');`
   * `cb.checked = true; cb.dispatchEvent(new Event('input', {bubbles: true})); cb.dispatchEvent(new Event('change', {bubbles: true}));`
4. **Клик «Подписать и отправить»:**
   * Кнопка: `document.querySelectorAll('button, a')` с текстом `Подписать и отправить`.
5. **Подтверждение в модальном окне:**
   * Контейнер `#modal`, поиск кнопки `Подписать и отправить` (или `Согласие`).
6. **Выгрузка документации (карточка закупки `/customer/p/purchase/view`):**
   * Поиск кнопки/ссылки с текстом `Выгрузить`.
   * Инициация скачивания ZIP-архива.
7. **Возврат в реестр.**
8. **Простановка статусной метки «Подготовить документы»:**
   * Ссылка в строке: `row.querySelector('a[href*="action=set_documents"]')`.
9. **Обновление фильтра реестра:**
   * Кнопка `Применить фильтры` для скрытия уже запрошенных лотов.

## 4. Целевая архитектура: Внешний Python Playwright-робот через CDP

Вместо нестабильного юзерскрипта внутри страницы реализуется внешний локальный агент на Python.

### Схема работы:
1. Оператор запускает штатный браузер с криптопровайдером (Chromium-ГОСТ / Яндекс.Браузер) с портом отладки:
   ```cmd
   chrome.exe --remote-debugging-port=9222 --user-data-dir="C:\chrome_gost_profile"
   ```
2. Оператор единоразово входит в АСТ ГОЗ по аппаратному ключу (ЭЦП).
3. Запускается локальный скрипт `scripts/ast_goz/playwright_cdp_downloader.py`.
4. Скрипт подключается к уже открытому браузеру через Chrome DevTools Protocol (`connect_over_cdp("http://localhost:9222")`).
5. **Критическое преимущество:** Реестр открыт в первой вкладке и **никогда не перезагружается**. Обработка каждого лота ведется во **второй (временной) вкладке**, которая закрывается после перехвата скачивания (`page.expect_download()`).

### Пакетный сбор (Air-Gap Delivery):
* Скрипт сохраняет скачанные архивы в папку: `C:\AST_GOZ_DOCS\<НомерПроцедуры>\<НомерПроцедуры>.zip`.
* По окончании сессии ГОЗ архивы переносятся в аналитический контур `tender-rag-api` для прогона через воронку отсева (Нацрежим -> Сроки/Аванс -> ТН ВЭД).
